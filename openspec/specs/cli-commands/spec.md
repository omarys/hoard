# Cli-commands Specification

> Generated by openlore v1.2.0 on 2026-10-07 15:46

## Purpose

Encapsulates command-line interface definition and argument parsing for hoarded commands, global
flags, and CLI subcommands.

## Requirements

> `src/cli_commands.rs`

> `src/cli_commands.rs`

> `src/gpt.rs`

### Requirement: Prompt

The system SHALL the service must query the openai chat api with the user prompt and api key, and return a parsed hoardcmd or a descriptive error command upon failure.

#### Scenario: SuccessfulCommandGeneration
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A valid user prompt and a working OpenAI API key
- **WHEN** prompt is invoked with the input and key
- **THEN** A POST request is sent to the OpenAI Chat API and the resulting content is parsed into a valid
HoardCmd

#### Scenario: APINetworkOrConnectionFailure
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** An invalid API key or a network failure during the API call
- **WHEN** prompt is invoked
- **THEN** An error HoardCmd named 'Something_went_wrong' is returned detailing the HTTP request error

#### Scenario: APIResponseDeserializationError
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** An unexpected or malformed JSON payload returned by the OpenAI endpoint
- **WHEN** prompt is invoked
- **THEN** An error HoardCmd named 'Something_went_wrong' is returned detailing the parsing error

### Requirement: FromGptString

The system SHALL the service shall parse formatted key-value lines from a gpt response string and populate the fields of a hoardcmd.

#### Scenario: ProperlyFormattedGPTResponse
- **GIVEN** A response string containing prefixed name, explanation, tags, and command lines
- **WHEN** from_gpt_string is invoked
- **THEN** A HoardCmd is constructed with the extracted name, description, tags, command, and namespace set to
'gpt'

#### Scenario: ResponseMissingCommandOrMalformed
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** A GPT response string lacking a valid command line
- **WHEN** from_gpt_string is invoked
- **THEN** The returned HoardCmd contains an error note in its description indicating that response parsing
probably failed

> `src/hoard.rs`

### Requirement: Load

The system SHALL load configuration from the specified path or default location, open the trove database, and load all stored commands.

#### Scenario: LoadWithCustomConfigDirectory
- **GIVEN** A custom configuration home path is provided
- **WHEN** load is called with Some(path)
- **THEN** Configuration and the trove database MUST be loaded from that path

#### Scenario: LoadWithDefaultConfigDirectory
- **GIVEN** No configuration path is provided
- **WHEN** load is called with None
- **THEN** Configuration and the trove database MUST be loaded from the default user config path

### Requirement: Start

The system SHALL parse and execute the requested cli subcommand, interactively managing commands, imports/exports, or searches, and return the chosen command string and autocomplete flag.

#### Scenario: ExecuteCLISubcommandSuccessfully
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A valid Cli argument structure
- **WHEN** start is called
- **THEN** The requested subcommand operation MUST execute and return the resulting command string and whether
it was an autocomplete invocation

### Requirement: ShowInfo

The system SHALL display the filesystem paths of the active configuration file and trove database to the user.

#### Scenario: PrintConfigurationAndDatabasePaths
- **GIVEN** An initialized Hoard instance with resolved paths
- **WHEN** show_info is called
- **THEN** The configuration and trove database file paths MUST be printed to stdout

> `src/main.rs`

### Requirement: RunApplication

The system SHALL parse cli arguments, load hoard application state, execute the parsed command, and output the resulting command string.

#### Scenario: SuccessfulCommandExecutionWithAutocomplete
<!-- openlore-test: tags=smoke,regression (auto) -->
- **GIVEN** Valid command line arguments indicating autocomplete behavior
- **WHEN** main is called
- **THEN** Outputs the command to standard error and returns Ok(())

#### Scenario: SuccessfulCommandExecutionStandardOutput
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** Valid command line arguments producing non-empty command output without autocomplete
- **WHEN** main is called
- **THEN** Outputs the command to standard output and returns Ok(())

#### Scenario: EmptyCommandOutput
- **GIVEN** Valid command execution that produces empty or whitespace-only output
- **WHEN** main is called
- **THEN** Produces no output and returns Ok(())

> `src/store.rs`

### Requirement: OpenDatabase

The system SHALL opens or creates the sqlite database at the specified path, applies migrations, and imports any legacy trove.yml file if the database is newly created.

#### Scenario: OpenExistingDatabase
<!-- openlore-test: priority=low (auto) -->
- **GIVEN** An existing SQLite database file at path with valid schema
- **WHEN** open is called with the path
- **THEN** A configured Db instance is returned without importing legacy YAML

#### Scenario: CreateNewDatabaseAndImportLegacyYAML
<!-- openlore-test: priority=low tags=smoke (auto) -->
- **GIVEN** The database file does not exist at path, but a sibling legacy trove.yml file exists
- **WHEN** open is called with the path
- **THEN** The database is created, migrated, and populated with commands from the legacy YAML file

### Requirement: LoadCommands

The system SHALL loads all commands stored in the database ordered by rowid.

#### Scenario: RetrieveCommandsSuccessfully
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A database populated with command records
- **WHEN** commands is called on Db
- **THEN** All command records are retrieved and mapped to HoardCmd structures

### Requirement: SyncCommands

The system SHALL replaces the entire command set in the database with the provided commands in a single atomic transaction, validating entries before saving.

#### Scenario: SyncValidCommands
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A slice of valid HoardCmd objects
- **WHEN** sync is called on Db
- **THEN** Existing commands are deleted and new commands are inserted within a transaction

#### Scenario: SyncInvalidPythonCommand
<!-- openlore-test: tags=regression (auto) -->
- **GIVEN** A HoardCmd of Python kind missing mandatory fields
- **WHEN** sync is called on Db
- **THEN** An error is returned and transaction is not committed

### Requirement: CheckLocalTroveExists

The system SHALL checks whether a local trove exists in the current directory, either as a sqlite database or a legacy yaml file.

#### Scenario: LocalTrovePresent
- **GIVEN** Either trove.db or trove.yml exists in the working directory
- **WHEN** local_trove_exists is called
- **THEN** Returns true

#### Scenario: LocalTroveAbsent
- **GIVEN** Neither trove.db nor trove.yml exists in the working directory
- **WHEN** local_trove_exists is called
- **THEN** Returns false
