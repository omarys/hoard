# Core Specification

> Generated by openlore v1.2.0 on 2026-10-07 15:46

## Purpose

Encapsulates and describes domain error conditions raised during command validation and management.

## Requirements

> `src/core/error.rs`

> `src/core/mod.rs`

### Requirement: GenerateShellCommand

The system SHALL the service must generate a shell invocation string formatted appropriately for execution depending on whether the stored command kind is shell or python.

#### Scenario: ShellCommandRetrieval
- **GIVEN** A HoardCmd instance with kind Shell and raw command 'git status'
- **WHEN** shell_command is called
- **THEN** The raw shell command string 'git status' is returned unaltered

#### Scenario: PythonCommandFormatting
- **GIVEN** A HoardCmd instance with kind Python and script contents
- **WHEN** shell_command is called
- **THEN** A base64-encoded python3 inline execution command string is returned

> `src/core/parameters.rs`

### Requirement: GetParameterCount

The system SHALL counts the number of parameter token occurrences within a command string. the service shall return zero if the command is a python script.

#### Scenario: CountParametersInStandardCommand
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** A shell command string containing parameter tokens
- **WHEN** get_parameter_count is called with the target token
- **THEN** It MUST return the exact number of token occurrences in the command

#### Scenario: BypassCountingForPythonScript
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** A command configured with CommandKind::Python
- **WHEN** get_parameter_count is called
- **THEN** It MUST return 0 regardless of token presence in the script text

### Requirement: ReplaceParameter

The system SHALL substitutes the next matching parameter pattern bounded by start and end tokens with a specified replacement value using regex. the service shall return an unaltered command if the command kind is python.

#### Scenario: ReplaceParameterBoundedByStartAndEndTokens
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** A command string with bounded parameter markers like #param!
- **WHEN** replace_parameter is called with start_token '#', end_token '!', and a replacement string
- **THEN** It MUST return a new HoardCmd where all matching patterns are replaced by the value

#### Scenario: PreservePythonCommandUntouched
- **GIVEN** A command configured with CommandKind::Python
- **WHEN** replace_parameter is called
- **THEN** It MUST return an identical clone without performing replacements

### Requirement: WithInputParameters

The system SHALL iteratively prompts the user via terminal dialog for each parameter token found in the command string and replaces it with the input value until no parameters remain.

#### Scenario: InteractiveParameterPopulation
<!-- openlore-test: priority=high (auto) -->
- **GIVEN** A command string containing one or more parameter tokens
- **WHEN** with_input_parameters is called
- **THEN** It MUST prompt the user for each parameter in sequence and replace tokens with the entered values

#### Scenario: NoParametersPresent
- **GIVEN** A command string with no parameter tokens or a Python command
- **WHEN** with_input_parameters is called
- **THEN** It MUST immediately return the command without displaying prompts

> `src/core/secrets.rs`

### Requirement: RedactSecrets

The system SHALL the service shall scan a command string for sensitive credentials against configured redaction rules and replace detected secrets with delimiter-wrapped parameter placeholders.

#### Scenario: CommandContainsSensitiveSecrets
- **GIVEN** A command string containing plain-text credentials such as passwords, tokens, or private keys
- **WHEN** redact_secrets is called with the command and token delimiters
- **THEN** Secrets are replaced with parameter placeholders and a Redacted object containing the transformed
command and redaction details is returned

#### Scenario: CommandDoesNotContainSecrets
- **GIVEN** A command string free of any sensitive patterns or credentials
- **WHEN** redact_secrets is called
- **THEN** The command string is returned unchanged and the redactions list is empty

### Requirement: WithRedactedSecrets

The system SHALL the service shall inspect a command object for secrets, replacing any found in the command text with placeholders and returning the updated command object alongside redaction metadata.

#### Scenario: RedactCommandObjectContents
- **GIVEN** A HoardCmd instance with raw command text containing secret credentials
- **WHEN** with_redacted_secrets is invoked with parameter delimiter tokens
- **THEN** A new HoardCmd instance with sanitized command text and an accompanying Redacted structure are
returned

### Requirement: IsClean

The system SHALL the service shall determine whether any redactions were applied to the command.

#### Scenario: NoSecretsWereRedacted
- **GIVEN** A Redacted instance with an empty list of redactions
- **WHEN** is_clean is called
- **THEN** True is returned

#### Scenario: OneOrMoreSecretsWereRedacted
- **GIVEN** A Redacted instance containing at least one recorded redaction
- **WHEN** is_clean is called
- **THEN** False is returned

### Requirement: Summary

The system SHALL the service shall compile a sanitized, human-readable summary description of all applied redactions without leaking the actual secret values.

#### Scenario: GenerateRedactionSummary
- **GIVEN** A Redacted instance containing applied redactions with placeholders and descriptive labels
- **WHEN** summary is called
- **THEN** A comma-separated string formatting each placeholder and label is returned without revealing the
underlying secrets

### Requirement: GetCommandCollision

The system SHALL the service shall locate any existing command that collides with the specified command's name and namespace.

#### Scenario: CollisionExists
- **GIVEN** A command sharing the same name and namespace already present in the Trove
- **WHEN** get_command_collision is called with the target command
- **THEN** The colliding command is returned

#### Scenario: NoCollisionExists
- **GIVEN** No command in the Trove matches the name and namespace of the target command
- **WHEN** get_command_collision is called
- **THEN** None is returned

#### Scenario: SortCommandsByUsageCountDescending
- **GIVEN** A Trove collection containing commands with varying usage counts
- **WHEN** get_commands_sorted_by_usage is called
- **THEN** A list of commands sorted from highest usage count to lowest is returned

The system SHALL the service shall remove all commands belonging to a specified namespace, returning an error if none were found.

#### Scenario: PurgeNamespaceCommands
- **GIVEN** One or more commands associated with namespace 'dev'
- **WHEN** remove_namespace_commands is called with 'dev'
- **THEN** All commands matching 'dev' are removed from the collection

- **WHEN** remove_namespace_commands is called with 'nonexistent'

#### Scenario: PickAndParameterizeCommand

#### Scenario: MergeNewCommandsFromSecondaryTrove
- **GIVEN** Another Trove containing commands not present in the current Trove
- **WHEN** merge_trove is called with the other Trove
- **THEN** The new commands are incorporated and true is returned

The system SHALL the service shall format and render the trove collection as a human-readable table to standard output.

#### Scenario: DisplayTroveTable
- **GIVEN** A populated Trove instance
- **WHEN** print_trove is invoked
