# Architecture Specification

> Generated by openlore v1.2.0 on 2026-10-07 15:46

## Purpose

This document describes the architectural patterns and structure of the system.

## Architecture Style

Layered architecture: Presentation (CLI argument parsing, shell integration, and interactive
terminal UI) → Application/Domain (command lifecycle, parameterization, filtering, and secret
redaction) → Persistence and External Services (SQLite storage and OpenAI API integration).

## Requirements

### Requirement: LayeredArchitecture

The system SHALL maintain separation between:
- Presentation (CLI & TUI) (Parses command-line arguments, drives interactive terminal rendering, handles keyboard event streams, and manages UI view state transitions.)
- Core Domain & Application Logic (Coordinates command workflows, manages in-memory troves, evaluates search filters, performs parameter token substitution, and handles sensitive credential redaction.)
- Persistence & Infrastructure (Provides persistent database access, manages database schema migrations, imports legacy YAML formats, and coordinates external LLM API calls.)

#### Scenario: LayerSeparation
- **GIVEN** a request from the presentation layer
- **WHEN** business logic is needed
- **THEN** the presentation layer delegates to the business layer
- **AND** direct database access from presentation is prohibited

### Requirement: SecurityModel

The system SHALL implement security via: Local single-user trust model with no multi-user authentication or role-based access control. Security focuses on credential leakage prevention via SecretRedactionService, which scans commands for passwords, tokens, and API keys to replace them with parameter placeholders prior to storage. OpenAI API key presence is verified via KeyNotSetControls for AI features, though whether the key is loaded from an environment variable or local configuration file is uncertain from the provided analysis.

#### Scenario: AuthenticatedAccess
- **GIVEN** an unauthenticated request
- **WHEN** accessing protected resources
- **THEN** access is denied

## Layer Structure

### Presentation (CLI & TUI)

**Purpose**: Parses command-line arguments, drives interactive terminal rendering, handles keyboard event streams, and manages UI view state transitions.
**Location**: `src/hoard.rs (MainEntryService, CliCommands), src/gui/commands_gui.rs (CommandsGui, EventService), src/gui/list_search/controls.rs (ListSearchControls), src/gui/list_search/render.rs (ListSearchRenderer, HoardTheme), src/gui/new_command/controls.rs (NewCommandControls), src/gui/parameter_input/render.rs (ParameterInput), src/gui/gpt/controls.rs (GptControls, KeyNotSetControls), src/shell.rs (ShellService)`

### Core Domain & Application Logic

**Purpose**: Coordinates command workflows, manages in-memory troves, evaluates search filters, performs parameter token substitution, and handles sensitive credential redaction.
**Location**: `src/core/trove.rs (Trove, HoardCmd), src/core/secrets.rs (SecretRedactionService), src/core/parameter.rs (ParameterService), src/core/filter.rs (FilterService), src/core/error.rs (HoardError), src/hoard.rs (Hoard orchestrator)`

### Persistence & Infrastructure

**Purpose**: Provides persistent database access, manages database schema migrations, imports legacy YAML formats, and coordinates external LLM API calls.
**Location**: `src/store.rs (StoreService), src/gpt.rs (GptService), src/installer.rs (HoardInstaller)`

## Data Flow

User invocation (CLI args or TUI terminal events) → CLI/TUI controller dispatch → prompt/command
validation and secret redaction (SecretRedactionService) → interactive parameter substitution
(ParameterService) or AI generation via GptService → in-memory trove aggregation (Trove/HoardCmd) →
SQLite database persistence via StoreService; selected commands are routed back to terminal stdout
or shell line buffers.
